# Fine-tuning ByteProof's local model

The goal of this pipeline is a small Qwen3-4B or 8B model that is genuinely
good at *proofreading* — a narrow task where a 4B fine-tune can outperform a
generic 8B model. It is the same model class ByteProof already downloads from
the Local AI tab, so the app does not need any new runtime code once a
fine-tuned GGUF is published.

## Pipeline

1. **Prepare data**

   ```bash
   pip install -r requirements.txt
   python prepare_data.py --max-train 50000 --max-eval 2000
   ```

   Public sources: BEA-2019 / W&I+LOCNESS (`bea2019st/wi_locness`), JFLEG
   (`jhu-clsp/jfleg`). CoNLL-2014 is used by researchers as a test benchmark
   only. Add synthetic pairs (strong model correcting realistic academic
   drafts) as JSONL in `synthetic/` — this is where ByteProof's academic
   context (citations, math, PhD chapters) gets its edge.

2. **Train a LoRA**

   ```bash
   python finetune_qwen.py \
       --base-model Qwen/Qwen3-4B \
       --output-dir output/byteproof-qwen3-4b-lora \
       --epochs 2 --batch-size 4 --lora-r 16
   ```

   Budget roughly: 50k pairs × 2 epochs ≈ 100k steps-equivalent of examples;
   on a single 24 GB GPU this is a few hours at 4B, longer at 8B. QLoRA
   (`--quantize`) cuts VRAM to ~8 GB for 4B with a small quality cost.

3. **Evaluate**

   ```bash
   python eval_grammar.py \
       --model output/byteproof-qwen3-4b-lora \
       --eval-file data/byteproof-gec/eval.jsonl
   ```

   Aim: ≥ 95% exact match on the eval split, < 2% unchanged output, mean edit
   similarity ≥ 0.95. If the model "explains" instead of editing, the
   training data or prompt needs tightening — ByteProof's runtime prompt says
   "return only the corrected text", and the training format must match it
   exactly.

4. **Merge, convert, quantize, publish**

   ```bash
   python finetune_qwen.py --merge-only --output-dir output/byteproof-qwen3-4b-lora
   # with a llama.cpp checkout:
   python llama.cpp/convert_hf_to_gguf.py output/.../merged --outtype f16
   llama.cpp/llama-quantize <f16.gguf> byteproof-qwen3-4b-Q4_K_M.gguf q4_k_m
   ```

   Upload the GGUF to your CDN (or a Hugging Face repo), publish a
   `byteproof-models.json` manifest (see `src/local_model.py`), and users will
   see the ByteProof-tuned model as a download in Settings → Local AI.

## Licensing notes

- Qwen3 is Apache 2.0 — safe to bundle and redistribute in a paid app.
- BEA-2019 is a shared-task dataset for research; verify its terms before
  redistributing any derived dataset. Synthetic data generated by you from
  your own drafts is cleanest for commercial distribution.
- Keep the ByteProof trademark out of the model weights; name it e.g.
  `bytemind-qwen3-4b-proofreader`.

## What makes proofreading-specific fine-tuning work

- **Output format is everything.** Small models are far more reliable when
  every example says "return only the corrected text" than when they are
  asked to explain.
- **Surgical edits beat rewrites.** Prefer training pairs with minimal edits
  (BEA-2019 style) and only add creative/rewrite pairs for the Creative mode.
- **Protect citations and math.** Add synthetic examples where the original
  contains `(Smith et al., 2020)`, LaTeX, or field codes and the correction
  leaves them untouched — the app's `protect_special_chars` logic already
  does this at runtime, and the model should learn to do it too.
